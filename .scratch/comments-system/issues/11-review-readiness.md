# 11: Готовность к ревью

**What to build:** проект готов к отправке. Страница отчёта на GitHub Pages показывает результаты прогона, покрытие, применённые методики и стек. README коротко объясняет запуск и ведёт на неё. Путь одного комментария можно показать шаг за шагом с тестом на каждом шаге.

**Blocked by:** 06, 07, 08, 09, 10.

**Status:** ready-for-human

## Страница отчёта

Решения приняты на гриллинге.

**Хостинг и сборка:**
- GitHub Pages. Публикуется из CI после каждого push в `main` (шаги `actions/upload-pages-artifact` и `actions/deploy-pages`, у job права `pages: write` и `id-token: write`). Один раз вручную: Settings → Pages → Source: «GitHub Actions». Это делает человек.
- В PR отчёт не публикуется: собранный сайт лежит артефактом job, его можно скачать из прогона.
- Результаты шардов `parallel` и job `serial` сводит в один отчёт отдельный job `report` после них. Он же собирает главную страницу. Локально то же собирает цель `make report`.

**Отчёт о прогоне: Allure.**
- Адаптеры для всех трёх раннеров: `allure-codeception` (unit и REST-regression), `allure-vitest` (unit JS), `allure-playwright` (smoke, REG-WS, e2e). Существующие JUnit-репортёры остаются: на них работают `tools/checks junit` и CI.
- Шаги `test.step` из Playwright видны в отчёте как шаги, trace и скриншоты падений приложены. Тесты сгруппированы по набору (unit, smoke, regression, e2e) и по ID.
- Истории прогонов нет: каждый прогон на `main` даёт свежий отчёт.
- Версию Allure (2 или 3) выбирает реализатор: та, у которой сборка отчёта проще встаёт в контейнер `node`.

**Главная страница** (`site/`, статическая, русский язык, названия инструментов как есть). Разделы, у каждого пункта одна-две ссылки на настоящие тесты:
1. **Итог прогона:** число тестов по наборам, прошло и упало, коммит и время прогона, ссылка в Allure.
2. **Покрытие кода:** строки PHP (pcov), строки и ветки JS (v8), ссылки на HTML-отчёты покрытия с разбивкой по файлам.
3. **Покрытие требований:** доля сценариев из `docs/test-plans/`, реализованных в тестах (из сверки ID), и матрица пути P1–P13 → ID тестов со ссылками.
4. **Пирамида и наборы:** unit, smoke, regression, e2e: зачем каждый, как работает, когда запускается локально и в CI, как масштабируется. Double-loop TDD по вертикальным срезам (ADR 0001).
5. **Техники тест-дизайна:** граничные значения (2/64/65, 2000/2001), классы эквивалентности (провайдеры невалидных данных), таблица решений (порядок ошибок валидации), переходы состояний (комментарий активен ⇄ удалён, состояния WS-соединения).
6. **Трассируемость и проверка тестов:** сверка ID в обе стороны, проверка тестов мутациями из комментариев к тикетам 05–10.
7. **Стабильность и правила:** ярусы, уникальные метки, seed, запрет sleep, retries 0, двойной и повторный прогон (тикет 09), коротко `rules.md`.
8. **Стек:** Yii2, PHP, Postgres, Redis, Workerman, Docker, Codeception, Vitest, Playwright, Allure, линтеры, GitHub Actions.
9. **Вне объёма:** нагрузочные тесты, заголовки безопасности, матрица браузеров, мутационное тестирование инструментом. Одной фразой: осознанно не делали.

- Ссылки на тесты, планы и ADR ведут на файлы GitHub по SHA коммита прогона, а не на `main`: так они не ломаются после следующих правок.
- Цифры (итог, покрытие, доля сценариев) подставляются при сборке из результатов прогона. Руками в странице их нет.
- Подробные объяснения живут только на странице. README их не повторяет, чтобы не держать две копии.

## Готово, когда

- [ ] README короткий: что за проект, как поднять, основные команды (`make up`, `make check`, `make report`), по строке о каждом наборе тестов и ссылка на страницу отчёта
- [ ] Allure-результаты пишут все три раннера, `make report` собирает отчёт и главную локально
- [ ] Главная содержит разделы 1–9 выше, цифры подставлены из прогона, ссылки ведут на файлы по SHA
- [ ] Job `report` в CI сводит результаты всех job. На `main` публикует на Pages, в PR кладёт сайт артефактом
- [ ] Страница открывается по ссылке Pages после слияния в `main`
- [ ] Сверка ID в обе стороны зелёная: каждый ID из `docs/test-plans/` реализован, и в тестах нет ID вне плана
- [ ] Двойной прогон `make check` с разными seed даёт одинаковый результат
- [ ] На чистой машине `make check` зелёный, CI на `main` зелёный
- [ ] Ручной проход P1–P13: на каждом шаге открыт тест, который его фиксирует
- [ ] Репозиторий опубликован, ссылка на репозиторий и на страницу отчёта готова к отправке
