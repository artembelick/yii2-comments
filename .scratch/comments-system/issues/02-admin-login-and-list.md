## Comments

**Реализация (ветка `slice/02-admin-login-and-list`).** `make check` проходит lint, unit (покрытие PHP 100%), smoke и regression и падает только на E2E-01, шаг 3: публичной части ещё нет. CI на GitHub в этом срезе не запускался, ветка не запушена.

Отклонения от плана. Все они внесены в `docs/test-plans/` в этом же срезе:
- `RateLimiterInterface` и `RateLimiter`. Ключ передаётся без префикса `rate-limit:`, префикс ставит сам `RateLimiter`. Адаптер `YiiRedisClient` покрыт новыми UNIT-RDS-01 и RDS-02.
- `LoginForm::login(string $ip)`: IP передаёт контроллер. Перегенерацию id сессии делает `user->login()`. В unit (LOGIN-03) она больше не проверяется, её проверяет REG-A-11.
- `admin/create` читает пароль из потока `input` контроллера, по умолчанию это STDIN. `PasswordReaderInterface` не понадобился. CLI-тесты работают с настоящим `AdminAccountService`, моки только на границах: репозиторий и часы. Из-за этого CLI-02 зависит от правил валидации сервиса.
- Покрытие PHP считается по приложениям, поэтому добавлены UNIT-USER-05 (`isBlocked`) и UNIT-UREPO-05 (успешный `create`).
- REG-A-13 проверяет вкладку «Удалённые», потому что страницы правки пока нет. Срез 06 должен вернуть сценарий со страницей правки. REG-A-13a проверяет попытки подменить `returnUrl` через HTTP (`X-Forwarded-Host`, `//evil.example`, `X-Rewrite-Url`), а сам разбор `returnUrl` проверяет UNIT-AUTH-02.
- У E2E-01 К0 получает текущее время БД, а не «вчера». БД не очищается, поэтому с датой «вчера» К0 ушёл бы со страницы 1 под данные regression.
- В ИЗ-5 (`rules.md`) добавлены исключения для UNIT-FIX и UNIT-MSG-01.
- Codeception PhpBrowser ходит на стенд через `CURLOPT_CONNECT_TO: ['::nginx:']`: curl сам резолвит `*.localhost` в 127.0.0.1.

Что осталось открытым:
- Seed Faker детерминирован по ID теста, а БД стенда не очищается. Поэтому повторный прогон regression или e2e на том же стенде без `make stand-down` падает на уникальном логине админа: метки совпадают с прошлым прогоном. `make check` каждый раз поднимает свежий стенд, и там проблемы нет.
- Замечания `/code-review`, которые оставлены на усмотрение:
  - в A-30 действие состоит из трёх `grabTextsOfPage`;
  - хост `http://admin.comments.localhost` зашит в тестах;
  - unit-тесты формы входа мокают компоненты `user`, `session` и `security`, так написано в плане LOGIN.

**Исправления после `/code-review`.**
- Лимит входа: попытка засчитывается через `hit` до проверки пароля, решение принимается по значению INCR. Раньше шли отдельные GET (`isExceeded`) и INCR после проверки, и пачка параллельных запросов проходила мимо лимита. Строки UNIT-LOGIN-02, 03 и 04 в `unit.md` обновлены. `isExceeded` в коде больше не вызывается, но остаётся в интерфейсе (UNIT-RL-03): удалять его — отдельное решение по плану.
- `returnUrl` с управляющими символами или пробелами (`/\t/evil.example` браузер превращает в `//evil.example`) уводится на список. Кейсы добавлены в UNIT-AUTH-02 и в план.
- Тексты `admin/create` и ответа 400 на неизвестную вкладку перенесены в каталог: `admin.unknown_tab` и раздел «Консоль» в `messages.md` (`cli.admin.*`).

- ЧТ-1 в `rules.md` уточнён под PHP: имя теста с ID стоит в `#[TestDox]` (unit) или первой строкой docblock (Cest). Так уже работает сверка ID. Все Cest-ы этому следуют.

Замечания на усмотрение, которые оставлены:
