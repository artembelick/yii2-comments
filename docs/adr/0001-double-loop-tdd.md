# Double-loop TDD по вертикальным срезам

Работа идёт вертикальными срезами: каждый срез проводит одно наблюдаемое поведение через все слои (миграция, модель, сервис, контроллер, view, JS) вместе с его тестами. Внутри среза два цикла:

- **Внешний цикл (приёмочный).** Срез начинается с e2e-сценария из `docs/test-plans/e2e.md`, который описывает поведение среза глазами пользователя. Он пишется первым и остаётся красным, пока срез не готов. Сквозной сценарий E2E-01 (путь комментария P1–P10) пишется во втором срезе и зеленеет по шагам: каждый следующий срез продвигает место его падения дальше.
- **Внутренний цикл (TDD).** Пока внешний тест красный, код пишется через red → green → refactor: один unit- или regression-тест из тест-плана, минимальный код до зелёного, рефакторинг, следующий тест. Каждый тест сначала падает по правильной причине.

Срез готов, когда его внешний тест зелёный, все тесты предыдущих срезов зелёные и `make check` проходит.

## Considered Options

- **Все тесты до кода, заморозка тегом `tests-locked`, отдельный имплементатор.** Отклонено. ~250 тестов против заглушек описывают воображаемое поведение: пока кода нет, нельзя проверить, как Yii на самом деле отвечает на невалидную форму, как ведут себя flash и CSRF. Ошибка в ожидании всплывает поздно и сразу в десятках замороженных тестов, а зафиксированная заранее карта классов не даёт рефакторингу улучшать дизайн.
- **TDD без внешнего цикла.** Отклонено: без приёмочного теста не видно, что срез доведён до конца с точки зрения пользователя, и нечем показать путь комментария на ревью.

## Consequences

- Тест-планы в `docs/test-plans/` — каталог сценариев с ID и исходный дизайн, а не контракт. Если TDD показывает, что ожидание или сигнатура неудачны, тест-план правится в том же срезе вместе с тестом и кодом.
- Порог покрытия 100% (строки и методы для PHP, строки, функции и ветки для JS) действует с первого среза на весь существующий код, кроме views, config, миграций и entrypoint-скриптов. Тонкий слой `ws/runtime/` над статикой Workerman считается entrypoint: линтер запрещает в нём ветвления и циклы, его покрывают smoke, e2e и REG-WS.
- Обходы запрещены линтером: `@codeCoverageIgnore`, `@phpstan-ignore`, `markTestSkipped`, `skip`, `only`, baseline.
- Сверка ID: каждый тест несёт ID из тест-плана, и линтер падает на ID, которого в плане нет. Тикет среза перечисляет свои ID; в финальном тикете сверка проверяет и обратное: каждый ID плана реализован.
