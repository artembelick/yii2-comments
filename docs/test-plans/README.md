# Тест-планы

Тест-планы — каталог сценариев с ID и исходный дизайн. Тесты пишутся по ним срезами через double-loop TDD (см. [ADR 0001](../adr/0001-double-loop-tdd.md)): сначала приёмочный e2e среза, затем unit и regression по одному тесту. Если TDD показывает, что сценарий неудачен, план правится вместе с тестом. В имени теста стоит полный ID с префиксом набора: `UNIT-VAL-01`, `REG-G-13`, `REG-A-08a`, `REG-WS-01`, `SMOKE-01`, `E2E-01`. В таблицах внутри своего раздела ID могут быть записаны коротко (`G-13` в разделе REG-G). Линтер падает на ID, которого нет в плане, а в финальном тикете проверяет, что реализован каждый ID плана.

| Набор | Файл | Инструмент | Что проверяет | Когда запускается |
|---|---|---|---|---|
| unit | [unit.md](unit.md) | Codeception (PHP, pcov) + Vitest (JS, coverage-v8) | Классы и JS-модули изолированно, без сети и Redis. В БД ходят только тесты репозиториев и AR: тестовая Postgres, транзакция с откатом. Порог 100%: для PHP строки и методы, для JS строки, функции и ветки | На pre-push, в CI на каждый push и в `make check` |
| smoke | [smoke.md](smoke.md) | Playwright | Стенд жив: страницы открываются, вход работает, WS подключается. Ничего не создаёт | Сразу после подъёма стенда, первым из интеграционных наборов. В CI на каждый PR |
| e2e | [e2e.md](e2e.md) | Playwright | Путь комментария в настоящем браузере: гость, несколько админов, WS | Последним в `make check`, после regression. В CI на каждый PR |
| regression | [regression.md](regression.md) | Codeception REST (HTTP) + Playwright (WS-контракты) | Зафиксированные контракты: валидация, права, безопасность, идемпотентность. Плюс тест на каждый найденный баг | В `make check` после smoke, до e2e. В CI на каждый PR |

Правила написания тестов (изоляция, детерминизм, читаемость, проверки) собраны в [rules.md](rules.md). Они обязательны для всех наборов.

## Линтеры и правила тестов

**Принцип:** всё включено. Правило можно отключить только в конфиге и только с комментарием «почему». Inline-отключения в коде (`@phpstan-ignore`, `@codeCoverageIgnore`, `oxlint-disable`, `markTestSkipped`, `test.skip`, `test.only`) запрещены. Любой линтер роняет `make check`, baseline нет.

**PHP:**
- phpstan уровня `max` с `phpstan-strict-rules`, `phpstan-deprecation-rules` и расширением `yii2-extensions/phpstan`. Без `bleedingEdge`: правила из будущих версий phpstan меняются при обновлении и дают шум на магии Yii2;
- php-cs-fixer;
- rector в режиме `--dry-run`;
- phpcs со `slevomat/coding-standard` для лимитов:

  | Лимит | Значение |
  |---|---|
  | Строк в файле | до 500 |
  | Операторов в методе | до 35 |
  | Параметров | до 5 |
  | Цикломатическая сложность метода | до 10 |

**JS/TS:**
- oxlint, все категории на уровне `error` и type-aware: те же лимиты плюс до 20 зависимостей на модуль;
- форматтер oxfmt в режиме `--check`;
- `tsc --noEmit` в strict.

WS-клиент написан на чистом JS без сборки, но с `// @ts-check` и типами в JSDoc, поэтому `tsc` проверяет его через `checkJs`. Для тестов и `/e2e` действуют отдельные overrides, тоже с причинами.

**Прочее:** hadolint для Dockerfile, `composer validate --strict`, сверка ID из тест-планов с именами тестов.

**Строгость тестов:**
- **Тест без проверок — ошибка.** В PHPUnit включены `failOnRisky`, `failOnWarning`, `failOnDeprecation` и `beStrictAboutTestsThatDoNotTestAnything`. В Vitest правило линтера требует `expect.hasAssertions()`.
- **Часовой пояс тестовых процессов зафиксирован: `TZ=UTC`** в PHP и в Vitest. Часовой пояс отображения (Europe/Moscow) передаётся явно.
- **Playwright:**
  - `retries: 0`, потому что флейк считается багом;
  - trace и скриншот при падении;
  - новый browser context на каждый тест;
  - `forbidOnly`.
- **Отчёты:** junit и покрытие (clover и cobertura для PHP, lcov для JS) пишутся в файлы.

## Запуски

**Локально:**
- `make check` прогоняет всё по порядку от быстрого к медленному: lint → unit (с порогом покрытия) → smoke → regression → e2e. Первый красный шаг останавливает цепочку.
- lefthook: на pre-commit линтеры по изменённым файлам, на pre-push `make test-unit`. Unit-тесты репозиториев ходят в тестовую Postgres, поэтому pre-push поднимает тестовый стенд, если он не запущен.

**CI (GitHub Actions):**

| Событие | Что запускается |
|---|---|
| push в любую ветку | lint, unit с покрытием |
| pull request и push в `main` | весь `make check`, разбитый на jobs: lint и unit; ярус `parallel` шардами; `pristine` и `exclusive` одним job. Каждый job поднимает свой стенд и сначала прогоняет smoke |
| по расписанию раз в сутки | весь `make check` дважды с разными seed случайного порядка (ловит зависимость тестов друг от друга) |

Отчёты junit, покрытие, trace и скриншоты Playwright сохраняются как артефакты прогона.

## Хосты на стенде

Публичная часть и админка живут на двух именах: `comments.localhost` и `admin.comments.localhost`. В сети compose у контейнера nginx есть alias'ы на оба имени, поэтому Codeception из php-контейнера ходит по ним как обычно. Chromium резолвит любой `*.localhost` в собственный 127.0.0.1 и DNS не спрашивает, поэтому Playwright запускает его с `--host-resolver-rules="MAP *.localhost nginx"`. Без этого браузер в контейнере Playwright стучится сам в себя.

## Где лежат тесты

| Тесты | Каталог |
|---|---|
| Codeception unit | Внутри приложений, как в yii2-app-advanced: `common/tests/unit`, `frontend/tests/unit`, `backend/tests/unit`, `console/tests/unit`, `ws/tests/unit`. Корневой `codeception.yml` собирает их все и считает общее покрытие |
| Codeception REST-regression | `frontend/tests/regression` (гость, REG-G) и `backend/tests/regression` (админ, REG-A) |
| Vitest | `backend/web/js/__tests__` |
| Playwright | `/e2e` на верхнем уровне проекта, со своим `package.json`. Проекты по набору и ярусу: `smoke`, `regression-ws-parallel`, `regression-ws-exclusive` (REG-WS), `e2e-parallel`, `e2e-exclusive`. Makefile запускает их по очереди в этом порядке |

## Работа с данными

- **Тестовый стенд** — отдельный compose-проект (`-p comments-test`, `docker-compose.test.yml`): свои Postgres с БД `comments_test`, Redis, ws и nginx, `YII_ENV=test`. Dev-данные не затрагиваются. После прогона стенд сносится.
- **БД создаётся один раз на прогон:** стенд поднимается, применяются миграции. Дальше БД не очищается, и тесты за собой не убирают.
- **Каждый тест создаёт свои данные с уникальной меткой.** Метка — это короткий uuid из Faker в имени автора, тексте или логине (`А-3f9c`). Тест ищет свои строки по метке и проверяет только их. Админы тоже создаются на каждый тест: блокировка, смена пароля и защита от подбора в одном тесте не задевают другие.
- **Данные, нужные до начала теста,** создают фикстуры, которые пишут в БД:
  - **Codeception:** Yii `ActiveFixture` с данными, сгенерированными на лету (уникальная метка и нужные поля: статус админа, `created_at`, `deleted_by`). Выгрузка (unload) и очистка таблиц отключены;
  - **Playwright:** фабрики в `e2e/support/factories.ts`, которые пишут в БД через `pg`. Имена и поля у них те же, что у PHP-фикстур (`admin`, `comment`). Работа со схемой БД собрана в этом одном модуле. Доступ к Redis стенда (сброс счётчиков лимита) собран в `e2e/support/redis.ts`.
- **Комментарии-предусловия всегда вставляются фикстурой в БД, а не через форму.** Форма гостя используется только там, где отправка и есть предмет проверки. Так форма не тратит лимит 5 в минуту.
- **Варианты входных данных внутри теста** берутся из data provider'ов: именованные наборы, одна проверка на набор.
- **Админ для smoke** один на прогон. Его создаёт `make admin` из `.env.test`, потому что smoke должен работать и на стенде, где создавать данные нельзя.

### Ярусы

Тесты стенда разделены на три яруса. В Codeception ярусы — это группы, в Playwright — проекты (см. «Где лежат тесты»). Makefile запускает их строго по очереди: smoke → REST-regression `pristine` → `parallel` → `exclusive` → REG-WS `parallel` → `exclusive` → e2e `parallel` → `exclusive`. Ярус `pristine` есть только у REST-regression: он идёт первым после smoke, пока БД пуста.

| Ярус | Когда идёт | Какие тесты | Условие |
|---|---|---|---|
| `pristine` | Первым в REST-regression, сразу после smoke | Пустые состояния: REG-G-02, REG-A-32 | БД пуста |
| `parallel` | Перед `exclusive` своего набора, можно параллельно | Тесты, которым достаточно своей метки: доступ по id, вход и права, правка, удаление и восстановление по id, WS-контракты по токену и сессии | Не зависят от чужих данных |
| `exclusive` | Последним в своём наборе, строго последовательно | Тесты, которые смотрят на первую страницу ленты или списка, порядок, баннер, «ровно одно событие», а также всё, где предмет проверки — отправка формы и rate limit | Никто другой не пишет в БД во время теста |

Ярус каждого сценария указан в тест-плане набора.

**Тесты яруса `exclusive`:**
- свои комментарии вставляют с самыми новыми датами, поэтому занимают начало ленты;
- все тесты Playwright приходят на стенд с одного IP, поэтому фикстура `guest` сбрасывает счётчик лимита этого IP через `e2e/support/redis.ts` перед тестом, а хелпер `postComment()` в Codeception — перед каждым POST. Исключение — сами тесты лимита (G-22).

**Масштабирование.** Локально всё идёт в один воркер. Ярус `parallel` без изменений в тестах раздаётся по воркерам и по шардам CI (`--shard` у Playwright, разбиение групп у Codeception): каждый тест работает только со своей меткой. В CI каждый шард — отдельный job со своим стендом. `pristine` и `exclusive` идут одним job последовательно. Если они станут узким местом, их тоже можно разбить на jobs по разделам плана: у каждого job свой стенд, значит своя пустая БД и свой лимит.

## Путь комментария

Вне пути комментария, но под тестами:
- logout и блокировка гасят WS: E2E-06, WS-08, WS-09, DSP-02, DSP-03, TERM, ACC, CLI, JS-WS-04;
- разрыв и переподключение: JS-WS-05…09, JS-BO, MH-08, CHK-02, CHK-03.

В колонке regression опущен префикс `REG-`, в колонке unit — `UNIT-`. В коде тестов ID всегда полные.
